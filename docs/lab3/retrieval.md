## Одиночні пошуки

hit@5 має успіх, якщо хоча б один gold_span дослівно міститься в поверненому фрагменті того самого doc_id. Absent виключені зі знаменника. Для multi окремо вимагаються всі уривки. Recall рахує частку знайдених gold_spans, MRR використовує найперший релевантний ранг. nDCG@10 звітується для поверненого списку довжиною до 5, решта позицій має нульову релевантність. Ці довідкові метрики не визначають рішення.

## Виміряне вікно embedder

bge-m3:latest дає **1024** компонентів вектора на першому реальному виклику. Індекс від 24 листопада містить 216 фрагментів. Вхід із 13056 символів заданого повторюваного українського тексту пройшов, 13184 повернув помилку **the input length exceeds the context length**. Це експериментальна дужка для цього тексту з truncate=False. Заявлене вікно тега 8K токенів і виміряний CONTEXT embedder=8192 не переводяться в символи постійним множником. Максимум власного фрагмента — 956 символів. CONTEXT чату — 16384. Сирі проби — results/lab3/00-embed-window.jsonl та 00-corpus-window.jsonl.

## Вибір на dev і RRF

У сітці dev усі сім варіантів дали 8/8 hit@5 і MRR=1. Це три режими lex, три відповідні гібриди та dense. За однакової якості кращим одиночним обрано lex через швидкість. Prefix залишено через знайдені відмінкові форми у морфологічній пробі. Налаштування не змінювалися за тестовими результатами.

| Параметр | Заморожене значення та обґрунтування |
|---|---|
| Фрагмент і перекриття | 1100 і 180 символів, абзацна межа, запас до виміряного вікна embedder |
| Модель і розмірність | bge-m3:latest, 1024, реальна відповідь /api/embed |
| Режим FTS5 | prefix, відмінкові форми знайдені на dev і морфологічній пробі |
| k_lex і k_dense | 20 та 20, для 216 фрагментів повний локальний прогін займає хвилини |
| top_k | 5, щоб залишити запас контексту для JSON і цитат |
| rrf_k | 60, константа пілоту [Cormack et al., SIGIR 2009](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf) |

CONFIG закомічений у 8abb2b8 до прогонів рішення test. Перевизначення mode/k дозволені лише на dev. Лексична й щільна побудови незалежні, розмірність і назва embedder перевіряються при запиті. Індекс відсутній у git та будується з chunks.jsonl.

Рішення обирає гібрид для доставки фрагментів у answer() та lex як дешевий одиночний контроль. Обидва мають 22/22 hit@5 на відповідних test, усі три multi знайшли всі потрібні уривки. Різниці за hit@5 не виявлено. Причина робочого гібрида — доступність семантичного ранжування при зміні формулювань. Твердження про перевагу гібрида на цьому наборі не робиться.

| Прогін | Медіана × запити | Розрахунковий час |
|---|---|---|
| Одиночний lex | 27 мс × 25 | 0.675 с |
| RRF | 2179 мс × 25 | 54.475 с |
| Dense | 2169 мс × 25 | 54.225 с |

Повна щільна індексація 216 фрагментів тривала 42.90 с, лексична 0.03 с. Скорочення корпусу або test не застосовувалось. Щаблина базова, налаштування лише на dev. При одному золотому уривку MRR та nDCG значною мірою дублюють позицію першого збігу. На цьому корпусі всі правильні джерела для одиночних запитів стоять високо, тому ці метрики додають мало.
