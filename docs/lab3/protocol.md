# Спільний протокол

Запити data/lab3/queries.jsonl, dev=8 і test=25. Базовий тег чату qwen3:0.6b. Контекст 16384, temperature=0, seed=7, max_tokens=768, reasoning_effort=none. Лінія prompting має лише 8 dev прикладів. Лінія rag додає пошук із замороженої retrieval_config.py. Лінія lora використовує адаптовані ваги без пошуку, з обліком обох ідентифікаторів ваг та SHA адаптера.

Ядро prompts/lab3-core-v1.md однакове байтово в усіх лініях. Надбудови збережені окремо. Для кожного рядка зберігаються core_prompt_sha256, overlay_sha256, line, параметри моделі та конфігурації. Prompting не має визначеної частки чинних цитат. RAG перевіряє цитати у фрагментах, фактично повернених пошуком.

Конфігурація пошуку обирається з dev, де всі сім конфігурацій дали 8/8 і MRR=1. Для одиночного порівняння вибрано lex через меншу затримку. Mode=prefix зберігає відмінкові форми в обов’язковій пробі. Гібрид використовує 20+20 кандидатів, RRF k=60, top_k=5. Перевизначення mode/top_k на test забороняє CLI.

## Контроль квантизації Q8, 24 листопада 2026 року

Після початкових прогонів встановлено, що готовий qwen3:0.6b має Q4_K_M, а адаптований імпорт використовує Q8_0. Тому основне порівняння повторюється в нових файлах 04-q8-prompting.jsonl, 04-q8-rag.jsonl та 04-q8-lora.jsonl. Неадаптовану базу Qwen/Qwen3-0.6B імпортовано окремим тегом lab3-qwen06-base:latest через той самий llama.cpp конвертер Q8_0, що й адаптовану lab3-qwen06-lora:latest. Квантизація, шаблон GGUF, контекст, запити, ядро та гіпотези однакові для цього порівняння. Змінюється джерело знань — dev few-shot, пошук або адаптер. Початкові 04-prompting/rag/lora зберігаються повністю як попередній контроль. Нові файли є звітними для lines/lines_flips. Правило оцінювання та expected не змінюються.

Для кроку 03 додано окремий 03-rag-q8.jsonl, щоб три числа відповіді відповідали робочій базі. Пул атак додатково повторюється в 03-attacks-q8.jsonl із тим самим корпусом, ядром і обгорткою. Так початкові й контрольні умови мають власні сирі файли.

Спільна метрика — правильність короткої відповіді. Нормалізований expected має міститися в нормалізованому першому рядку answer. Для absent достатня встановлена відмова без цитати. Порівняння ліній включає усі test, а окрема метрика відповіді кроку 03 виключає absent. Тестові запити й еталони не використовуються для підбору пошуку, few-shot або навчання.
