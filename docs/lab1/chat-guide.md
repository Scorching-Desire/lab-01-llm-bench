# Як виконати чат-порівняння

Це окремий експеримент: 3 чат-застосунки (ChatGPT, Claude, Gemini) і 1 локальна модель × 5 прикладів = 20 перших відповідей. API benchmark не замінює цей пункт.

## 1. Підготовка
- Увійди у ChatGPT, Claude і Gemini. Використовуй звичайний чат, без агента, вебпошуку, інструментів або завантаження всього набору.
- Перед дослідом вимкни використання розмов для навчання в кожному застосунку. Методичка називає перемикачі Improve the model for everyone / Help Improve our AI models / Keep Activity; назви можуть відрізнятися за мовою/версією. У ChatGPT почни з Settings → Data controls. Зафіксуй фактичні налаштування і дату; авторизацію й налаштування виконуєш особисто.
- Запиши назву моделі саме так, як показує UI; якщо не показує — «застосунок не показує». Не підставляй назву API-моделі за припущенням.
- Для всіх 5 запитів одного застосунку лишай незмінні модель і режим. Якщо один застосунок недоступний, дозволена заміна іншим провідним провайдером; поясни причину у chat-comparison.md.

## 2. Готові промпти
У chat/prompts/ лежать t01.txt, t07.txt, t08.txt, t24.txt, t25.txt. Кожен уже містить однакову інструкцію та дослівний input, без expected. t07/t08/t24/t25 — hard, t24/t25 — injection.

Для кожного застосунку повтори 5 разів:
1. Створи новий порожній чат.
2. Відкрий потрібний txt і встав **увесь текст без змін**.
3. Надішли один раз. Дочекайся завершення першої відповіді.
4. Скопіюй відповідь дослівно, включно з поясненнями/відмовою/огорожами JSON. Не натискай Regenerate і не виправляй модель уточненнями.
5. Збережи скриншот, а тоді переходь у новий чат для наступного id.

Не вставляй expected у повідомлення моделі. Відповіді оцінюй лише після отримання.

## 3. Скриншоти
Зручно робити Win+Shift+S вручну. У кадрі повинні бути назва моделі (або відсутність показаного ID), надісланий запит і відповідь. Для довгої відповіді зроби кілька кадрів; окремо збережи її повний текст.

Мінімум — доказ на кожен чат-застосунок і локальну модель; надійніше зберегти всі 20 клітинок. Імена файлів: chatgpt-t01.png, claude-t01.png, gemini-t01.png, local-t01.png тощо у docs/lab1/chat/.

Обріж ім’я акаунта, email, аватар із персональними даними, список інших чатів, сповіщення, ключі. Не обрізай і не змінюй сам зміст запиту/відповіді. Скриншот помилки доступу не є відповіддю моделі.

## 4. Локальна модель у PowerShell
Використовуй ту саму qwen3:1.7b, новий запуск CLI для кожного id. На цій машині Ollama встановлена в LOCALAPPDATA/Lab01-Ollama; сервер має працювати.

```powershell
$id = 't01'
$prompt = Get-Content -LiteralPath "docs/lab1/chat/prompts/$id.txt" -Raw -Encoding utf8
& "$env:LOCALAPPDATA/Lab01-Ollama/ollama.exe" run qwen3:1.7b --think=false $prompt
```

Повтори для t07, t08, t24, t25. Не запускай ollama run без аргумента промпту в спільному багатокроковому сеансі. Якщо Windows PowerShell 5.1 загубив подвійні лапки під час передачі argv, це невалідна спроба; використовуй PowerShell 7 і перевір цілісність тексту. На скриншоті термінала повинні бути тег моделі, команда і відповідь. Запиши, що thinking вимкнено; параметри CLI за замовчуванням не обов’язково збігаються з API benchmark.

## 5. Оформлення результатів
У chat-comparison.md для кожної з 20 клітинок додай:
- id прикладу, застосунок, фактичну назву моделі, дату і режим;
- дослівну відповідь у details (довгий текст не скорочувати);
- правильно/ні за golden.jsonl;
- «впевнена помилка: так», якщо відповідь хибна і без застережень;
- посилання на відповідний PNG.

Приклад оформлення (не результат експерименту):

```markdown
### ChatGPT · t01
Модель: назва з UI. Дата: фактична дата.
<details><summary>Дослівна перша відповідь</summary>

Тут встав повний текст фактично отриманої відповіді.

</details>
Правильно: так/ні. Впевнена помилка: так/ні.
![ChatGPT t01](chat/chatgpt-t01.png)
```

Після заповнення перевір: 4×5 клітинок, ≥2 hard і ≥1 injection серед п’яти входів, і хоча б одна з чотирьох моделей помилилася. Якщо всі 20 правильні, методичка вимагає складніших прикладів і нового огляду; не вигадуй помилку й не міняй expected заднім числом.

Скриншоти та дослівні відповіді можна передати в цю розмову або зберегти у вказаних файлах для перевірки й подальшого оформлення.
