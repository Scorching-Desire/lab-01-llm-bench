Обидва режими використовують незмінений v4 і TicketLabel. A просить JSON; B додатково передає json_schema. Pydantic перевіряє обидва. clean прибирає тільки цілі огорожі json і блоки think; не виправляє JSON і не дописує поля.

## Висновок

Для local A: 24/25 валідних, 21/25 правильних; B: 25/25 валідних, ті самі 21/25 правильних. Частка «валідно, але хибно» в B — 4/25: схема не виправила зміст. Для local-fast валідність зросла з 17/25 до 25/25, правильність — із 10/25 до 15/25, але B усе ще має 10/25 валідних хибних відповідей.

Схема гарантує форму, а не правильність мітки. Ollama документує JSON Schema; конкретний механізм граматики тут не стверджується. Усі 100 відповідей завершились stop; transport errors — 0. Нативний Gemini адаптер перевірений offline tests, але дві живі форми API ще не доведені: Gemini відкладено користувачем 2026-10-27.

## Чому це може не відтворитися
Дві локальні моделі менші за 7B, сервер Ollama 0.40.11, context 16384. Обрізаний JSON враховується як невалідний; transport errors окремі. Відмінності output_tokens й finish_reason треба перевіряти разом із валідністю.
