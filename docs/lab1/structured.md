## Висновок

Для local A: 24/25 валідних, 21/25 правильних; B: 25/25 валідних, ті самі 21/25 правильних. Частка «валідно, але хибно» в B — 4/25: схема не виправила зміст. Для local-fast валідність зросла з 17/25 до 25/25, правильність — із 10/25 до 15/25, але B усе ще має 10/25 валідних хибних відповідей.

Flash-Lite через gemini_native: A і B мають по 15/15 валідних і правильних, ДІ точності [0.80;1.00]. Медіани — 2583 мс і 2155 мс; середній output_tokens (разом із thinking, як повідомляє адаптер) — 122 та 120. На цій вибірці схема не дала приросту ні валідності, ні точності. Це не доказ рівності методів на всіх даних.

Схема гарантує форму, а не правильність мітки. Ollama документує JSON Schema; конкретний механізм граматики тут не стверджується. Усі 130 відповідей головної A/B-матриці завершились stop; transport errors — 0. Обидві форми API підтверджено наживо: OpenAI-сумісний Gemini у кроці 03 і native у кроках 04–05. Пілот 3.8 з 503/20-day quota збережено окремо в results/exploratory.

## Чому це може не відтворитися
Дві локальні моделі менші за 7B, сервер Ollama 0.40.11, context 16384. Обрізаний JSON враховується як невалідний; transport errors окремі. Відмінності output_tokens й finish_reason треба перевіряти разом із валідністю.
