## Транспорт і умови вимірювання
- Перші відповіді тривали приблизно 146 і 298 секунд; GET моделей через REST та OpenAI SDK водночас працював швидко. Діагностичні native REST/SSE запити не завершилися за 25/20 секунд. Це не виміри якості й не підмішані до test-таблиць.
- Перша test-спроба native B повернула 503 UNAVAILABLE: «This model is currently experiencing high demand». Її не видалено; наступна успішна спроба t01 дописана як attempt=2.
- Незавершений пілот 3.8 використовував **налаштовану максимальну concurrency=16**, загальний допуск не швидше 6 HTTP-запитів/хв, max_tokens=4096, reasoning/thinking low. Локальні дані лишаються з concurrency=1; пілотні затримки напряму не порівнюються з ними. Основна Flash-Lite матриця нижче має concurrency=1.
- Усі append/read захищені lock для потоків одного процесу; пропущені до відправлення завдання не отримують вигаданих рядків. Окремі tool-виклики також проходять спільне обмеження RPM.
- Стандартний runner повторює тимчасові 503/timeout до п’яти спроб; вичерпана квота припиняє нові завдання. Серверна помилка, що не зникла після повторів, також зупиняє видачу нових кейсів; уже надіслані завершуються.
- Модель 2.5 Flash не вибиралася замість 3.8: її одинична діагностична POST-перевірка повернула 404. Основні aliases/ID не підмінювались.

## Відновлення й перевірка
Команда для обраного Flash-Lite наведена нижче. 3.8 не продовжувався після добової квоти.
`--resume` виконується диспетчером для кожного id. При відновленні треба лишити ту саму concurrency, інакше потрібні окремі файли для нової експериментальної умови. Повноту визначає audit.py, а не наявність одного успішного запиту.

Стан результатів і кількість test-відповідей див. у згенерованих structured.md / prompts.md / tools.md та audit.md. Обрана Flash-Lite матриця завершена: 106/106 унікальних успішних кейсів, транспортних помилок у цих файлах немає.

## Основна матриця: окремий Flash-Lite кандидат
Після 503 і вичерпання 20/day для 3.8 вибрано gemini-3.1-flash-lite. REST-проба завершилася за 1.77 с (MAX_TOKENS при діагностичному ліміті 64, не оцінка якості); dev v4 дав 3/3 правильних через native та 1/1 через OpenAI-сумісний API. Картку й aliases зафіксовано до першого test; cloud-selection.json містить мотив, час і налаштування. Мітки та промпти не змінювалися.

Для повної матриці використовуються окремі файли gemini-lite / gemini-lite-native, concurrency=1, max RPM=8, low, max_tokens=4096. Це відновлює контрольоване порівняння з локальними проганами concurrency=1. Частота запитів обмежує throughput; latency одного HTTP-виклику не включає очікування перед його відправленням. Latency tool-кейсу включає увесь цикл.

Пілотні 3.8 A/B цілком перенесені у results/exploratory/04-*-gemini-native.jsonl; жодне поле/рядок не відредаговані. В основні таблиці вони не входять як незавершена quota-обмежена матриця; причина виключення також у report.load_rows. Audit перевіряє provenance і цих файлів.
