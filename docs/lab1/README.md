## Рішення
Вибір для локального використання після хмарного порівняння, обмежений цим синтетичним набором:

1. Модель requested/reported: `qwen3:1.7b` / `qwen3:1.7b`, псевдонім local; дата 2026-10-27.
2. Промпт v4, prompt_sha256 `c10566286251`.
3. Режим B, openai_chat через Ollama; без інструментів для golden-класифікації. Tool-випадки оцінені окремим t1, їхні числа не підмішуються у test.
4. Власні числа з [structured.md](structured.md): 21/25 = 0.84, 95% ДІ [0.65;0.94]; валідних 25/25; медіана 73 мс; валідно-але-хибно 4/25. API-ціна локального виклику $0, електроенергія й амортизація не оцінювалися.
5. Компроміс: v2 має більше правильних у повному test (23/25), проте його ДІ [0.75;0.98] перетинається з обраним. V4 обрано за поведінкою на t24/t25 і строгим форматом B. На спільній q15 B: local 13/15 [0.62;0.96], Gemini 15/15 [0.80;1.00], медіани 74 і 2155 мс. Інтервали перетинаються; статистичної переваги не встановлено. Для цього застосування обрано локальну швидкість і приватність: free-tier Gemini може використовувати вхід для покращення продуктів. Хмара показала кращий фактичний результат і є кандидатом, коли затримка/передача даних прийнятні. Схема не гарантує коректність дії.
6. Переглянути після нового незалежного набору, зміни digest/сервера, появи персональних даних або p95 понад 1.5 с. Перевіряти зміну цін і квот: сценарій `uv run python scripts/report.py --price gemini-lite=0.50/3.00 --price gemini-lite-native=0.50/3.00` подвоює поточну стандартну ціну лише арифметично, без API. Таблична ціна не є рахунком за free tier; апаратні витрати local окремо не оцінені.

## Що переходить у курсову
Стенд із двома наживо перевіреними API-адаптерами, детермінованим scorer, схемою, власним tool loop, локальними й хмарними результатами та тестами. Підтверджені студентом дані й гіпотези можна розвинути; справжню предметну вибірку й незалежну перевірку ще треба додати. Тема потребує підтвердження викладачем.
