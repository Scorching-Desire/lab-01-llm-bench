# Крок 05 · Перевірка та ремонт

Три незалежні правила перевіряють дату, діапазон суми та обов’язковість примітки для маршруту «інше». Невалідний JSON має статус invalid і не ремонтується. Для валідного документа з порушенням сервіс робить один повтор із тим самим документом та кодами правил. Повтор має межу 512 вихідних токенів і таймаут 60 с. Траси зберігають відповіді і час кожного завершеного ходу.

Знаменник усіх трьох часток — валідні документи з хоча б одним порушенням до ремонту. Для точності беруться спрацьовування, поля яких містили wrong/missing/spurious. Врятований документ має всі поля правильні після verified. Зламаний документ був повністю правильним до ремонту та має хоча б одну помилку після нього.

Ремонт Bonsai v1 запустився на s010 і s018 після порушення діапазону. Обидва лишилися flagged. V2 спрацював на s010, s016 та s018 із тим самим кодом. Усі три лишилися flagged. Правила виявляють частину хибних значень, а невірний номер форми MS-0000 може їх пройти. Їхнє завдання обмежене форматом і узгодженістю квитанції.

Окремий CLI запуск на s008, s011 та s019 дав **6137, 5151, 4533 мс** через Gemini B v1, усі verified після одного ходу. Медіана 5151 мс. Локальний Bonsai B v2 дав **3542, 3856, 3573 мс**, усі три пройшли правила. Цей вимір оцінює швидкість CLI та статус правил. Точність береться з кроку 04, де є еталон. Обидві медіани нижчі за 120 с.
